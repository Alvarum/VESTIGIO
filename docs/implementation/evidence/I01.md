# I01 — Acciones de input y settings comunes mínimos

Estado: **INTEGRATED**
Commit integrado: `683ad2d`

## Resultado

- El SDK define acciones estables y muestras `pressed`/`held`/`released`. El juego acumula transiciones y movimiento de mirada entre frames y publica una muestra por tick fijo; perder foco limpia estado y tiempo acumulado antes de reanudar.
- Player y Studio traducen sus entradas mediante el mismo mapa de bindings. Studio acumula `KeyUp` y `MouseUp`, por lo que un tap completo entre dos renders conserva tanto `pressed` como `released`.
- Los settings versionados resuelven `defaults → proyecto → usuario → sesión/CLI` sin modificar las capas de origen. Resolución interna, fullscreen, VSync, frame cap, bindings y sensibilidad llegan a los hosts y a la sesión compartida.
- Los overrides de sesión y CLI no se persisten. VSync y frame cap controlan presentación, sin cambiar el `dt` fijo de simulación.
- La persistencia valida el destino antes de reemplazarlo. Un archivo corrupto o de versión futura se conserva byte por byte; la escritura usa temporal sincronizado y reemplazo seguro.
- Las rutas UTF-8 se convierten a UTF-16 para abrir, reemplazar y eliminar archivos en Windows. El formato v1 es estricto: extensiones futuras requieren una versión nueva para impedir que un runtime antiguo destruya datos desconocidos.
- Las salidas públicas respetan `struct_size`: un prefijo no anuncia campos que no caben y puede reutilizarse en llamadas consecutivas sin sobrescribir el canario del consumidor.
