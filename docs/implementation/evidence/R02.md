# R02 — Registro de assets y ownership CPU/GPU mínimo

Fecha: 2026-09-20. Commit integrado: `9ed4d5e`.

## Resultado implementado

- `VgAssetId` persistente y separado del `VgAsset` efímero. Cada `acquire` o `clone` entrega un lease generacional independiente; liberar uno no invalida otros usuarios.
- Catálogo fuente separado del residente compartido, deduplicado por `AssetId` y variante. Fuente, opciones y ruta se copian con el allocator del contexto.
- Referencias externas y privadas de componentes con `purge` explícito. El recurso sólo es evictable cuando ambas cuentas llegan a cero.
- Decode CPU mediante decoder privado y upload/release GPU mediante executor del backend. Las operaciones gráficas verifican owner thread y nunca se ejecutan desde el decode.
- Recarga candidata transaccional: un fallo de decode u upload mantiene la versión CPU/GPU anterior, conserva su versión/fingerprint y expone diagnóstico.
- Contadores separados para catálogo, residentes, leases, referencias, estados, cache hits, uploads/releases y RAM/staging/VRAM estimada.
- Descriptores versionados con `struct_size/api_version`, validación de tipos/contexto/generación y outputs intactos ante error de versión.

## Ownership y límites

El contexto posee el registro. Un componente convierte un lease público en una referencia privada y puede sobrevivir a la liberación del lease original. Los payloads CPU conservan una copia de su decoder para usar el destructor correcto aunque cambie el decoder registrado.

El executor GPU se adjunta y se separa en su hilo propietario. `vg_context_destroy` exige ese mismo hilo mientras el executor siga adjunto; si se invoca desde otro, registra el error y deja el contexto vivo para permitir retry seguro. `vg_asset_detach_gpu` preflighta la cola antes de mutar y libera releases pendientes en el hilo admitido.

La implementación inicial admite Texture y Mesh. La contabilidad VRAM es una estimación informada por backend, no una lectura del driver. La carga es sincrónica en R02; el estado `LOADING` representa trabajo GPU pendiente y deja abierta una cola asíncrona posterior sin introducir threads ahora.

## Pruebas

`vestigio_assets` cubre:

- leases compartidos, clone, stale/doble release, contexto/tipo equivocado y component refs;
- una sola decodificación para dos usuarios y cache hit observable;
- owner thread, upload, release diferido, detach y destroy con retry desde hilo incorrecto;
- fallo parcial de upload, fallo de decode/OOM y recarga válida conservando la versión anterior hasta publicar;
- purge, contadores RAM/staging/VRAM y balance de destructores;
- fallos inyectados en cada allocation de registry/catalog sin publicación parcial;
- versiones de descriptor incorrectas sin sobrescribir outputs.
