# G02 — Superficie GPU embebida en Studio

Fecha: 2026-09-20. Base GPU integrada: `a13fb8beb89691d842709773abadb0b755d8f9a6`.

## Decisión de superficie

Studio usa un `HwndHost` WPF que aloja una ventana OpenGL 3.3 creada por raylib. El adaptador nativo obtiene el HWND creado por raylib, lo convierte en hijo del HWND provisto por WPF, elimina estilos de ventana superior y aplica `WS_CHILD`, clipping y tamaño físico. No intenta hacer que raylib adopte un HWND creado por WPF.

El hilo UI posee ventana, contexto y renderer. Sólo puede existir un `VgGpuHost` por proceso. Un compare/exchange atómico reserva ese ownership y cada operación comprueba el thread ID propietario. `BuildWindowCore` crea el host y se suscribe al pulso de composición; `DestroyWindowCore` y `Dispose` quitan la suscripción, destruyen recursos GPU y cierran la ventana/contexto. El viewport actual dibuja la escena diagnóstica G01; E01/G03 sustituyen esa entrada por `EditWorld` y modelos reales. El `GameViewport` CPU legacy permanece debajo durante el spike para no romper Play.

La presentación embebida no usa `EndDrawing`, porque raylib llamaría `PollInputEvents` y bombearía reentrantemente la cola completa de WPF. En su lugar vacía el batch y llama `SwapScreenBuffer`; el Dispatcher WPF es el único dueño del message pump. El HWND hijo usa `WS_TABSTOP` y un subclass nativo toma foco en `WM_MOUSEACTIVATE` y botones. El texto diagnóstico se dibuja dentro del render target GPU; el rótulo WPF queda fuera del rectángulo HWND para respetar airspace.

El frame normal ejecuta mesh, shader, textura, depth y presentación en GPU. No copia el framebuffer a `WriteableBitmap`. `vg_gpu_host_capture` es una operación de prueba explícita que incrementa readbacks y no participa en `CompositionTarget.Rendering`.

## Pruebas ejecutadas

`retro_studio_authoring` cubre:

- 50 ciclos secuenciales create → render → resize 320×180 a 640×360 → render → destroy sobre un HWND WPF;
- integración real de `GpuViewportHost`, foco nativo, dos frames, resize a 426×240 y liberación explícita;
- rechazo de segundo host simultáneo, llamadas desde hilo ajeno y fallback HWND sin cerrar Studio;
- documento AvalonDock `Probar` conectado una vez, composición y resize a 1280×800 y 1920×1080;
- captura solicitada desde el renderer alojado, decodificada como PNG 320×180.
- instalación del componente `Runtime` en prefijo limpio con `vestigio_gpu_host.dll` presente (4.422.088 bytes en debug).

Salida directa relevante:

```text
PASS GPU native host create/render/resize/destroy x50
PASS WPF HwndHost GPU render and resize
PASS WPF composition 1280x800, 1920x1080 (offscreen)
```

La prueba detectó durante desarrollo un segundo host activo al desacoplar sin `Dispose`; se corrigió haciendo explícita la liberación y manteniendo una superficie durante los cambios de docking/tamaño.

Captura reproducible local: `build/debug/studio-evidence/gpu-hwndhost.png`, SHA-256 `0C144C1758C3D2CAD5F34EFDF600AECC7B5510A888B8D317FDAFB1C6DE48C06A`. Inspección visual: fondo oscuro, rótulo GPU dentro del render target, cubo rojo con depth y billboard azul con alpha. G02 la obtiene a través del host WPF; no es el `RenderTargetBitmap` de WPF, que por la regla de airspace no captura el HWND hijo.

## Cobertura y límites observados

- PASS: superficie GPU nativa realmente embebida; no es una ventana externa ni un blit CPU por frame.
- PASS: ownership único, error/fallback ante segundo host, rechazo de hilo ajeno, resize físico comprobado con `GetClientRect`, cleanup y recreación 50 veces.
- PASS: 320×180 interno y presentaciones 426×240, 640×360, 1280×800 y 1920×1080.
- PASS automatizado: foco explícito al HWND. El subclass nativo cubre activación por mouse y `TabIntoCore` transfiere foco desde WPF.
- PARCIAL: el cálculo DPI maneja `OnDpiChanged`, usa `VisualTreeHelper.GetDpi` y convierte unidades WPF a píxeles, pero el entorno automatizado sólo expuso 96 DPI; 150 % y 200 % quedan para aceptación humana con monitor físico.
- NO VERIFICADO manualmente: tecla Tab/Escape completa, minimizar/restaurar, docking flotante/reacoplado y arrastre entre monitores. El render se suspende si la ventana está minimizada o desconectada de una `PresentationSource`. Se intentó abrir el ejecutable y el log confirmó “Ventana visible”, pero la herramienta de computer-use disponible en esta sesión no expone aplicaciones nativas. No se convierte ese intento en PASS.
- PENDIENTE: input común I01, `EditWorld` E01 y escena/modelos World G03/G04.

G02 queda verificado dentro de las capacidades disponibles; las comprobaciones humanas pendientes están identificadas y no bloquean R01/R02 ni el backend GPU.
